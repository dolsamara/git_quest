Крок 3 Створення нової гілки

git checkout — це багатофункціональна команда Git, призначена для перемикання між гілками, 
відновлення файлів робочого каталогу та переходу до певних комітів. Вона оновлює файли у вашій робочій
директорії, щоб вони відповідали версії в індексі або вказаній гілці. 
Основні функції git checkout:
📂 Перемикання гілок: 
    git checkout <branch_name> 
    перемикає робочий каталог на вказану існуючу гілку.
📂 Створення нової гілки:
    git checkout -b <new_branch_name>
    створює нову гілку і відразу перемикається на неї.
📂 Відновлення файлів:
    git checkout -- <file_name>
    скасовує локальні зміни у файлі, повертаючи його до стану останнього коміту.
📂 Перегляд комітів:
    git checkout <commit_hash>
    дозволяє переглянути стан проєкту на момент певного коміту (в стані "detached HEAD"). 

Примітка: У нових версіях Git для роботи з гілками рекомендують використовувати git switch (перемикання) 
та git restore (відновлення файлів), оскільки git checkout виконує забагато різних функцій.

🔹 Створи свою гілку
    git checkout -b feature/ваша-назва

Основні правила іменування гілок
  ❗️❗️❗️ Уникайте спеціальних символів: Не використовуйте пробіли, коми, символи, такі як ?, *, [, ], ~, ^, :, \ або ...
  🔸 Використовуйте малі літери: feature/login-page, а не Feature/LoginPage
  🔸 Розділяйте слова дефісом (-): Уникайте пробілів та нижніх підкреслень (_), використовуйте kebab-case
  🔸 Використовуйте префікси:
    feature/ — для нових функцій (наприклад, feature/user-auth).
    fix/ або bugfix/ — для виправлення помилок (fix/login-bug).
    hotfix/ — для термінових виправлень у продакшені.
    feature/ — для нових функцій.
    docs/ — для зміни документації.
    refactor/ — для рефакторингу коду.

Крок 4 Зміни

Далі перевірти змінені файли
    git status

Заіндексуйте змінні
    git add .

git add — це команда в системі контролю версій Git, 
    яка додає зміни з робочої директорії до індексу (staging area). 
    Це перший етап підготовки файлів перед фіксацією (коммітом), 
    що дозволяє вибрати, які саме зміни увійдуть до наступного знімка проекту.
Основні функції та команди:
  🔸 git add <файл>: Додає конкретний змінений файл до індексу.
  🔸 git add .: Додає всі змінені та нові файли в поточній директорії.
  🔸 git add -u: Додає лише змінені або видалені файли (без нових). 

Для чого використовується:
Формування комміту: Визначає, що саме буде збережено в історії.
Підготовка (Staging): Дозволяє підготувати зміни частинами, навіть якщо в одному файлі змінено багато різних речей.
Відстеження файлів: Додає нові файли під контроль Git.

Далі 
    git commit -m "Назвіть ваш комміт"

git commit — це команда в системі контролю версій Git, яка фіксує (зберігає) поточні зміни,
    додані до індексу (staging area), у локальному репозиторії. Кожен коміт є унікальною «знімком»
    (snapshot) стану проекту, який містить зміни, автора, час створення та повідомлення, що дозволяє
    відстежувати історію та повертатися до попередніх версій. 

Основні аспекти git commit:
Фіксація змін: Коміт не просто зберігає файли, а створює хеш-суму (ідентифікатор) стану проекту в конкретний момент.
Локальне збереження: На відміну від push, commit зберігає зміни лише на вашому комп'ютері.
Коментар (повідомлення): Кожен коміт повинен мати опис того, що саме було змінено (команда git commit -m "повідомлення").
Структура: Містить метадані, посилання на попередній коміт та знімок файлової системи. 

Популярні команди:
  🔸 git commit -m "опис" — зафіксувати проіндексовані зміни з повідомленням.
  🔸 git commit -am "опис" — додати всі відстежувані файли та зафіксувати.
  🔸 git commit --amend — виправити останній коміт.

Крок 5 Push
Напишіть команду
    git push origin feature/ваша-назва (ваша-назва - назва вашої гілки вона пишеться в круглих душках () та позначається синім в GitBush)

Команда git push використовується для надсилання ваших локальних
    змін у віддалений репозиторій. Ця команда актуалізує віддалений репозиторій,
    роблячи його вміст відповідним вашим локальним змінам. Коли ви готові поділитися
    своєю роботою з іншими розробниками або оновити віддалену гілку, git push стає невід'ємною частиною вашої роботи.
Виконайте команду git push, вказавши ім'я віддаленого репозиторію (наприклад, origin) та гілку (наприклад, main):
$ git push origin main
Ця команда відправить зміни вашої локальної гілки main у віддалений репозиторій origin.
Важливі зауваження:
    Якщо ваша локальна гілка ще не була пов'язана з віддаленою гілкою, ви можете використовувати опцію -u для встановлення відповідності між ними: git push -u origin main.
    Перед виконанням git push переконайтеся, що ви внесли всі необхідні зміни та зробили комміти.
    У випадку, якщо у віддаленому репозиторії відбулися зміни після вашого останнього git pull, перед виконанням git push рекомендується виконати git pull для об'єднання змін .
Команда git push відіграє ключову роль у колективній розробці, забезпечуючи оновлення віддаленого репозиторію з вашими локальними змінами.


Крок 6 Merge
Команда git merge застосовується для об'єднання змін з однієї гілки до іншої.
    Зазвичай це використовується, щоб внести зміни з окремої гілки назад до основної галузі розробки,
    такої як main або master. Процес об'єднання, відомий як "злиття" (merge), дозволяє створити єдиний стан,
    що включає зміни з різних гілок.

Переконайтеся, що ви знаходитесь у гілці, в яку ви хочете внести зміни. Наприклад, для перемикання на гілку main використовуйте:
    git checkout release
Виконайте команду git merge, вказавши гілку, з якої ви хочете внести зміни (наприклад, feature/ваша-назва):
    git merge feature/ваша-назва
Ця команда зливає зміни з гілки feature/ваша-назва у вашу поточну гілку (release). Якщо зміни не конфліктують, Git автоматично створює новий коміт із об'єднаними змінами.

Важливі зауваження:

Якщо є конфлікти злиття, Git повідомить вас про це, і вам доведеться вирішити їх вручну перед завершенням злиття.
Можна виникнути ситуація "fast-forward", коли Git може об'єднати зміни, не створюючи нового комміту. Це відбувається, коли ваша цільова гілка не змінилася з моменту створення гілки для злиття.
Якщо у вас є незбережені зміни у вашій поточній гілці, Git може вимагати від вас зробити коміт або скасувати зміни перед тим, як виконати злиття.
Команда git merge забезпечує гнучкість в управлінні змінами та інтеграції нових функцій у основну лінію розробки.
